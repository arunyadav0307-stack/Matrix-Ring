## 2. How a requester asks

The author asks requesters to include, in a single email:

1. **Name and affiliation** (so the request is not anonymous).
2. **What is being requested** — either "the complete supplementary package" or
   a named subset, using the file names in
   `PHASE21_PRIVATE_DATA_INVENTORY.csv`.
3. **Why** — the purpose: reproduction of a stated result, verification of a
   certification, extension of the work, or peer review.
4. **Preferred transfer method**, if the requester has one (see §5).

A request missing (1) or (3) should be answered by asking for the missing
item, not refused.

---

## 3. How the request is evaluated

"Reasonable request" is applied as follows. A request is **reasonable** when
its purpose is scholarly — reproducing a published number, checking a
certification, extending the construction, or reviewing the manuscript — and
when what is asked for is inside the inventoried package.

| case | action |
|---|---|
| Purpose is scholarly; material is in the inventory | **Provide.** Normally within 14 days. |
| Purpose is scholarly; subset requested rather than the whole package | **Provide the subset.** This is the common case and is encouraged — most requesters need one generator matrix or one log, not 86 files. |
| Purpose is commercial exploitation of the material | **Decline or restrict**, at the author's discretion. |
| Material requested is **outside** the inventory (working files, internal audit documents, phase reports, correspondence) | **Default: do not provide.** These are not part of the research data underlying the published results. The author may still provide them if they choose; nothing obliges them to. |
| Request is anonymous, or the purpose is not stated | **Ask for the missing information.** |
| Volume of requests becomes burdensome | The author may publish a repository deposit at that point, which would resolve the matter permanently. **Not done, and not authorised.** |

The author is not obliged to answer a request that is abusive, or to enter into
correspondence beyond supplying the material.

## 5. How the material is transferred

| size | method |
|---|---|
| Up to ~10 MB (a subset, or the whole package — the complete package is about 2.4 MB) | Email attachment, or a single `.zip` of `PAPER/supplementary/` |
| Anything larger, or if email is unreliable | A download link generated by the author, sent by email |

Two rules:

1. **Always include `MANIFEST.sha256`.** It is part of the package and it is
   what makes the transfer verifiable.
2. **Send the package as it stands.** Do not re-run the scripts to "refresh"
   the logs. The value of the package is that it is byte-identical to the
   computation that produced the published numbers; re-running would change
   the elapsed-time annotations and invalidate the log hashes.

A pre-made archive is not required — `PAPER/supplementary/` is already a
self-contained directory and can be zipped directly.

## 6. How integrity is checked

The requester verifies what they received with:

```bash
cd supplementary
sha256sum -c MANIFEST.sha256
```

Expected result: **85 lines, all `OK`, 0 `FAILED`.** (85 hash lines cover the
86 files; the manifest does not list itself.)

If any line reports `FAILED`, the transfer was corrupted and must be repeated.
The author should quote this command when sending the material, so the
requester knows to run it.

For a single file rather than the whole package, the requester can check that
one file against the SHA-256 recorded in the `sha256` column of
`PHASE21_PRIVATE_DATA_INVENTORY.csv`.

Reproduction, once integrity is confirmed, is documented in
`PAPER/supplementary/README.md` and in Appendix B of the manuscript:

```bash
cd supplementary/scripts
python3 phase7_extended_search.py > out.txt 2>&1     # ~9 minutes, ~370 MB RSS
```

Pure Python 3 standard library; no third-party package is required.

## 7. Third-party and restricted material

**One file** in the package contains external third-party content:

| file | what it is | handling |
|---|---|---|
| `parameter_tables/comparison_grassl_q9.csv` | Best-known $q=9$ stabilizer distances (3 rows), read from codetables.de on **2026-11-04** and quoted verbatim | **Provide unmodified**, together with its provenance note. Cite as `\cite{GrasslCodetables}` in the manuscript. Do not edit, "correct" or re-derive the values. |

These are publicly published tables, not restricted data; the constraint is
provenance and attribution, not confidentiality.

Everything else in the package is the author's own original work. The scripts
use **only the Python standard library** — no numpy, sympy, Sage, GAP or Magma
— so no third-party licence is engaged by the code, and no third-party licence
restriction applies to any other file.

Two standing cautions for the author:

* **No licence has been chosen for this repository.** GitHub reports
  `licence: NONE`, which under copyright law defaults to "all rights
  reserved". Supplying files privately on request does not grant the requester
  a licence to redistribute them. If the author wants requesters to be able to
  reuse the material freely, a licence choice is needed — **this is deferred at
  its existing status and was not touched in this phase.**
* If a requester asks for material **outside** the inventory, the default
  answer is no (see §3). Internal audit documents, phase reports and working
  files are not part of the research data underlying the published results.

## 8. What this procedure does not do

* It does **not** create a data repository, a DOI, a Zenodo deposit, a GitHub
  release, a public tag or a public download URL.
* It does **not** establish a data-sharing service. It is a procedure the
  author follows manually.
* It does **not** make the material public. Requests are answered
  individually.
* It does **not** by itself satisfy FFA Option C. That question is open and is
  put to the editorial office in
  `PHASE21_EDITORIAL_CLARIFICATION_EMAIL.md`.
